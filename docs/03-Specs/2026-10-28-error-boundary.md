# 错误边界

> **状态**：已批准（D1–D4 由用户在[审阅页](https://claude.ai/artifact/SipHt4ZePfFqcty8Q178EX)选定，2026-10-28）
> **级别**：S1
> **日期**：2026-10-28
> **Backlog**：B5

## 目标

页面渲染出错时不再整页白屏。用户能看到出了什么问题，并能自己恢复：重试、重置当前项目，或者切到别的页面。

## 非目标

- 错误上报或遥测（不变量：外部请求数 = 0）。
- Worker 内部错误（`runPixelTask` 已有 `onerror` 处理）。
- 事件处理器 / Promise 里的异步错误 —— React 错误边界捕获不到；按 D4 本次不做，已记入 Backlog B8。
- 错误详情展示（D3=B）。

## 用户决策

- **D1 = A**：错误边界包住 Layout 里的 `<Outlet />`，顶栏和页脚保留；最外层再加一个兜底。
- **D2 = A**：错误卡片上放「重试」「重置当前项目」「返回首页」。
- **D3 = B**：不显示错误详情。
- **D4 = A**：异步错误本次不做，记入 Backlog。

## 假设

- 「重置当前项目」调用当前路由对应 store 的 `actions.clear()`：`/single` → editorStore，`/batch` → batchStore，`/split` → splitterStore。首页和指南页没有 store，不显示这个按钮。
- 重置前沿用现有的 `window.confirm(t('editor.clearConfirm'))` 确认。
- 「重试」只复位错误边界、重新渲染，不动 store；切换路由时错误边界自动复位（key 取 pathname）。
- 错误照常 `console.error`，不发送到任何地方。
- 视觉验证需要能触发错误：只在 DEV 构建中提供 `?crash=1` 触发器，生产构建不包含。

## 行为与验收标准

1. 某页面组件渲染时抛错：顶栏导航和页脚仍然可用，主区域显示错误卡片，包括标题、一句说明和恢复按钮，中英双语；卡片上不显示错误信息。
   - 「返回首页」跳到 `/`，在首页出错时不显示这个按钮。
2. 点「重试」：如果错误不再出现，页面恢复，store 数据保留。
3. 点「重置当前项目」并确认：该页 store 被清空，页面回到上传区。
4. 出错后点导航切到其他页：目标页正常显示；再切回出错页时会重新尝试渲染。
5. Layout 本身抛错：显示最外层兜底页，只有「刷新页面」一个按钮。
6. 全程外部请求 0。
7. 测试：组件测试用会抛错的子组件，覆盖卡片渲染、重试复位、各路由重置分别调用对应 store 的 `clear`、路由切换复位；Playwright 在 dev 服务器上用 `?crash=1` 截图（中、英各一张）。
