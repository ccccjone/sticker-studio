# 批量上传内存预算（防崩溃）

> **状态**：已批准（参数由用户在决策台选定，2026-10-28）
> **级别**：S1（bug 修复 + 跨模块改动；参数已定，无待决问题）
> **日期**：2026-10-28
> **Backlog**：B1 · 配套 [B7 加载体验](./2026-10-28-batch-loading-ux.md)

## 目标

批量上传在最坏输入下也不让标签页崩溃：峰值内存 ≤ **512 MiB**（估算，按最坏的正方形大图）。

## 用户决策（决策台）

| 项 | 值 |
|---|---|
| 单批最多 | **4 张**（批量列表总数，替代原 50） |
| 单张最长边上限 | **4096 px**，超出则解码时等比缩小 |
| 并发解码 | **3** |
| 原图存储 | 只留压缩文件（File），导出时逐张重解码 |
| 峰值预算 | 512 MiB |

## 非目标

- 单图页、拆分页的内存策略不变（各只有 1 张原图；拆分页缩小原图会降低切片清晰度）。
- 加载占位与取消（B7）。
- 资源释放审计（B6）。

## 现状问题

1. `batchStore.addFiles` 用 `Promise.all` 同时解码全部文件。
2. 只限文件 ≤ 20 MB，不限像素；8000² JPEG 解码约 250 MiB，浏览器内部完整解码一次、画布再一份、`getImageData` 又一份。
3. 每个条目常驻原分辨率 `ImageData`（`EditorItem.image`）。

## 方案

1. **读文件头取尺寸（不解码）**：`core/imageHeader.ts` 解析 PNG（IHDR）、JPEG（SOFn）、WebP（VP8 / VP8L / VP8X）。读不到 → 按「未知尺寸」最大权重处理。
2. **按像素加权的并发队列**：`core/weightedQueue.ts`，同时最多 3 个任务，且在途像素总量 ≤ 3 × 4096²；单个超大任务独占运行。支持取消（B7 用）。
3. **解码到上限尺寸**：批量解码时按文件头尺寸算出 ≤ 4096 的目标尺寸，用 `createImageBitmap(file, { resizeWidth, resizeHeight, resizeQuality: 'high' })`；不支持 resize 选项的浏览器降级为全尺寸解码再画到目标尺寸。只生成**代理图**（≤ 1536），不保留原图像素。
4. **原图来源抽象**：`EditorItem.image: RasterImage` 改为 `source: ImageSource`（`{ width, height, load(): Promise<RasterImage> }`）。
   - 单图 / 拆分：常驻来源（`load` 直接返回内存中的图），行为不变。
   - 批量：文件来源（`load` 时按上限尺寸重解码；不缓存）。
   - 所有导出路径（单张导出、批量 ZIP、拆分 ZIP）改为 `await source.load()`；ZIP 本来就是串行，峰值只多一张。
5. **预算锁定测试**：`core/memoryBudget.ts` 提供最坏峰值估算；测试断言「当前常量（4 张、4096、并发 3、代理 1536）」的估算 ≤ 512 MiB。以后谁调大常量，测试就红。

## 行为与验收标准

1. 选 6 张 → 只加入 4 张，其余以「超过单批 4 张上限」拒收；列表计数显示 `n / 4`。
2. 一张 6000 × 3000 的图加入批量后，代理图最长边 1536；导出画布 4096 时，导出从 4096 × 2048 的重解码原图重算（像素断言：导出图非空、尺寸正确）。
3. `imageHeader` 对 PNG / JPEG（含 EXIF 前置段、progressive SOF2）/ WebP 三种变体返回正确尺寸；截断或非图片返回 null。
4. `weightedQueue`：任意时刻在途 ≤ 3；在途权重 ≤ 上限；超大任务独占；取消排队中的任务不会执行；单个任务失败不影响其他任务。
5. 估算测试：当前常量下最坏峰值 ≤ 512 MiB。
6. 批量条目不再持有原分辨率像素（单测：`addFiles` 后条目上没有原图 `RasterImage`，只有 `source.load`）。
7. 单图、拆分页现有测试全部保持通过；Playwright：批量上传 4 张 → 导出 ZIP → 4 张 PNG + manifest，外部请求 0。

## 假设

- 浏览器的 `createImageBitmap` resize 能在 Chrome / Edge / Firefox 降低解码峰值；Safari 若不支持则降级（峰值较高但受并发权重约束）。
- 「已透明」检测改在代理图上做（缩小不会让含透明的图变成不透明）。
