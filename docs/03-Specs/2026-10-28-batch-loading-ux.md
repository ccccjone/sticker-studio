# 批量上传加载体验

> **状态**：已批准（样式由用户在决策台选定，2026-10-28）
> **级别**：S1
> **日期**：2026-10-28
> **Backlog**：B7 · 依赖 [B1 内存预算](./2026-10-28-batch-memory-budget.md)

## 目标

选完文件后立刻有反馈，逐张看到进度，不必干等全部完成。

## 用户决策

- 样式 **B · 模糊渐显**：先显示模糊低清图，处理完成后过渡为清晰图。
- 附加：**先出低清缩略图**、**按选择顺序逐张就位**、**排队中可取消**。

## 非目标

- 单图页、拆分页的加载反馈（已有 Spinner，保持不变）。
- 主画布的渐进加载。

## 行为与验收标准

1. 选择文件后同一帧内，缩略图列表按选择顺序出现每个文件的占位行（文件名 + 阶段标签），列表计数立即包含它们。
2. 阶段：`排队中` → `解码中` → `去背景` → 完成。阶段标签中英双语。
3. **低清缩略图先行**：进入解码前，用文件头尺寸生成 ≤ 96 px 的小图（`createImageBitmap` 缩放解码），以模糊样式显示；拿到代理图后显示代理缩略图（仍模糊）；去背景完成后过渡为清晰（`prefers-reduced-motion` 下无过渡）。
4. **逐张就位**：每张完成即成为可点选、可编辑的正常条目，位置保持选择顺序，不等其他文件。第一张就绪时自动成为当前条目（与现在一致）。
5. **取消**：`排队中` 的行显示 ✕，点击后从队列移除，不再解码；已开始解码的不可取消（只可在完成后删除）。
6. 解码失败的行转为现有的拒收提示，并从列表移除。
7. 首次上传期间（还没有任何就绪条目）显示列表 + 画布区占位，而不是回到空的上传区。
8. 单测（store）：顺序就位、取消排队项、失败移除、阶段推进；组件测试：占位行渲染与取消按钮。Playwright：上传 4 张，截图记录中间态（至少一张模糊 + 阶段标签），最终全部清晰。

## 假设

- 低清缩略图只用于显示，不参与任何像素计算；生成失败时直接跳过（仍显示文件名占位）。
- 「去背景」阶段沿用现有自动预应用逻辑（已透明的图跳过该阶段）。
