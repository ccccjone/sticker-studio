# 从失败中改进工作流

依据 ai-agent-book 第 9 章：不是把每次抱怨追加进 prompt，而是识别作用域、提出最小更新、验证后再发布。

## 1. 记录（每次都做，30 秒）

追加到 `docs/05-Reviews/lessons.md` 的"记录"表：

| 日期 | 现象（一句话） | 根因 | 来源（commit / plan / 对话） | 次数 |

同类现象已存在时，不新增行，把"次数"+1 并补来源。

## 2. 升级为规则的门槛

同时满足才提议修改规则：

- 同类问题出现 **≥2 次**；
- 能用一句"作用域 + 动作 + 例外 + 验证方式"说清楚；
- 不是一次性的环境问题（网络、依赖版本抖动）。

## 3. 放在哪一层

| 作用范围 | 载体 |
|---|---|
| 能用程序确定性检查 | `.claude/hooks/`、lint 规则、`verify.sh`、测试——**优先** |
| 只在某类任务相关 | 对应的 `.claude/skills/*/SKILL.md` |
| 所有任务都相关 | `CLAUDE.md`（保持短，改动要少） |
| 事实 / 知识（不是行为） | `docs/` 下对应文档或 ADR |

## 4. 提案格式（交给用户批准，不要自行改 CLAUDE.md）

```
规则提案：<一句话>
放在：<文件路径>
diff：<最小改动，只加/改几行>
来源：lessons.md 第 N 行（次数 X）
可能误伤：<哪些正常情况会被这条规则影响>
```

批准后在 lessons.md 对应行标注"→ 已升级：<文件>"。

## 5. 定期整理（每个 Phase 结束）

- 删掉已被 hook/lint 覆盖的文字规则；
- 合并重复规则，CLAUDE.md 保持在一屏以内；
- 次数一直是 1 且超过一个 Phase 的记录，归档。
